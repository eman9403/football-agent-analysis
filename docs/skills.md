# Skills for this project

These skills are already installed globally in Codex, so this repository points to them rather than copying their files. Codex may select a relevant skill from its description; name one explicitly when you want a particular workflow.

| Work | Skill | Use it when |
| --- | --- | --- |
| Clarify a feature and its terms | `grill-with-docs` | A scouting request is ambiguous or the domain language needs to be recorded. |
| Check data/API claims | `research` | Selecting a dataset, interpreting its documentation, or checking a library integration. |
| Shape a clean module | `codebase-design` | Defining the ingestion, query, or AI boundary. |
| Build a vertical slice | `tdd` | Adding behavior that has a testable input and output. |
| Diagnose a failure | `diagnosing-bugs` | A data import, API call, model output, or UI flow fails. |
| Review a completed slice | `code-review` | Checking the diff against the sprint exit criteria. |
| Keep changes focused | `ponytail:ponytail` and `karpathy-guidelines` | Routine implementation and review. |
| Maintain agent guidance | `writing-for-agents` | Editing `AGENTS.md` or adding a future project skill. |

A project-specific `SKILL.md` should be added only after a repeated football-data or evaluation workflow has concrete steps that the existing guidance does not cover. Project rules that apply to every task belong in `AGENTS.md`; source and architecture details belong in their dedicated docs.

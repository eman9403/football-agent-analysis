# Scouting interface direction

The working visual identity is **Touchline**: a dark scouting console with the energy of match analysis and the clarity of a professional recruitment tool. This is a design direction, not a claim of a finalized product name or trademark.

## What the interface should do

A scout should quickly see the state of the workspace, move into player search, compare evidence, and understand where a report's claims came from. Lead with usable controls and data when those features exist. Sprint 0 only has service health, so its football pitch graphic explains the planned path from data to search to report without pretending to show player data.

## Visual rules

- Use charcoal `#101413` for the canvas and `#191e1b` for working surfaces. Divide areas with fine `#363e38` rules rather than floating cards and heavy shadows.
- Use electric lime `#d5f650` for active selection, key evidence, and successful connection. Reserve warm amber `#f5ab6c` for unavailable services and caution. State must also be written in text.
- Use Barlow Condensed for strong, compact display headings and DM Sans for readable interface text. Both fonts are bundled locally.
- Use pitch geometry and tactical routes when they explain a workflow or data relationship. Avoid decorative football imagery that competes with player evidence.
- Keep movement restrained: route flow and live signals may move softly, with reduced-motion support. Future charts should animate only when the change helps a scout understand a comparison.
- On narrow screens, stack the pitch and status panels without horizontal scrolling. Make the current action and service state easy to find.

## Future screens

Player profiles should read like dossiers: role and competition context first, then comparable metrics with units, coverage and source. Search results should support fast scanning and direct comparison. AI-written reports should visibly separate retrieved facts from interpretation. Do not fill empty states with invented player statistics.
